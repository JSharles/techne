# Techne asks its questions in the lesson page, not in the conversation

The hosts Techne runs on suggest a reply in their input field, so a question asked in the conversation can hand the learner its own answer before they have thought about it. Two sessions of real use showed it happening on graded questions and, the next day, on a Socratic question asked mid-debug. Techne therefore asks nothing in the conversation: questions live in the browser lesson, and debugging proposes an experiment to run rather than a question to answer.

This is a workaround for a host behaviour, not a pedagogical principle. On a host that does not suggest replies — a custom interface, or a terminal whose input stays empty — the constraint can be lifted and questions can return to the conversation, which is where they naturally belong.

## Consequences

- Any surface Techne gains must be checked for the same leak before questions move onto it.
- The rule is written in the skill with its cause and this expiry condition, so it is not inherited as pedagogy by a future product.
