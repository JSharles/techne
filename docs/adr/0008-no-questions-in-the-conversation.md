# Techne asks exercise questions in the lesson page, not in the conversation

The hosts Techne runs on suggest a reply in their input field, so a question asked in the conversation can hand the learner its own answer before they have thought about it. Two sessions of real use showed it happening on graded questions and, the next day, on a Socratic question asked mid-debug. Techne therefore asks no exercise question in the conversation: those questions live in the browser lesson, and debugging proposes an experiment to run rather than a question to answer.

This is a workaround for a host behaviour, not a pedagogical principle. On a host that does not suggest replies — a custom interface, or a terminal whose input stays empty — the constraint can be lifted and questions can return to the conversation, which is where they naturally belong.

The rule covers the questions that belong to an exercise, whose answer the learner is meant to find: placement questions, quizzes, recalls, lesson checks, and diagnostic questions during debugging. It covers nothing else. Questions the learner is meant to decide rather than find — exploring the red-thread product, choosing a scope, calibration, planning, orientation — and operational exchanges such as which folder to use or confirming a reset are asked in the conversation, where a suggested reply gives nothing away.

This scope was made explicit on 2026-09-21, after the rule was read as forbidding every question and Techne refused to hold a product exploration in the conversation.

## Consequences

- Any surface Techne gains must be checked for the same leak before questions move onto it.
- The rule is written in the skill with its cause and this expiry condition, so it is not inherited as pedagogy by a future product.
